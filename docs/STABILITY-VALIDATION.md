# セッション起動・書き戻しの確認

今回の修正は既存の clipboard-only 経路を維持し、GUI 非表示と前面復帰の順序、
UIA のフォーカス認識待ち、キー送信直前の対象確認、クリップボード所有 HWND を扱う。

## 自動テスト

- GUI 完了応答前には書き戻しへ進まない。復帰失敗、応答経路の切断、タイムアウト、アプリ終了を扱う。
- UIA の子フォーカスが遅れて戻れば待ち、別ウィンドウなら直ちに中止する。別入力欄は許可しない。
- Windows の実クリップボードで日本語・複数行・空文字を往復し、所有 HWND 破棄後も読めることを確認する。
- 既存の保存／破棄契約、Neovim 起動・再起動、クリップボード provider のテストも実行する。

## Windows 11 実機

1. サインイン直後、最初の Ctrl+Alt+E でメモ帳・ブラウザ textarea・普段使うチャットの入力欄を開く。
2. Ctrl/Alt を少し長く押してから離す場合も確認する。非編集領域ではウィンドウを開かない。
3. 日本語・空行・複数行を編集し、`:wq` と `ZZ` を各 20 回繰り返す。
4. `:w` 後の `:q!`、保存なしの `:q!`、変更なし終了が既存の契約どおりになることを確認する。
5. 復帰中に別ウィンドウや別入力欄へ移った場合、そこへ全文貼り付けされないことを確認する。
6. クリップボードを他アプリが一時占有している場合と、CPU 負荷が高い場合も確認する。
7. Neovim の再起動に失敗した後、原因を解消してホットキーで再試行できることを確認する。

失敗時は `%LOCALAPPDATA%\anvi-data\log\anvi.log` の `cannot start a session`、
`write-back failed`、`no editable target after focus discovery wait` と前後のログを確認する。
エラーは原因チェーンまで記録するが、入力テキストは記録しない。

## 残る制約

コピーの 400 ms タイムアウトは空欄との区別ができず、既存仕様では空欄として扱う。
貼り付け後の 150 ms 待ちは取り込み完了の保証ではなく、重いアプリでは復元が早すぎる可能性がある。
UIA の COM 呼び出し自体が停止する場合も、今回の再試行期限では強制中断できない。
これらの解消には完了確認・編集結果の保持・クリップボード復元方式の別途検討が必要。
